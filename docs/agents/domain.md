# Domain docs

This repository uses a single-context layout:
`GLOSSARY.md` at the root and architectural decisions under `docs/adr/`.

Before exploring an area, read the glossary and any relevant ADRs that exist.
If they are absent, continue without creating placeholder documents.
Create them when domain-modeling work resolves an actual term or decision.

Use established glossary terms in issues, proposals, code, and tests.
Surface conflicts with an existing ADR explicitly.

For product behavior and visual changes, also read `PRODUCT.md` and `DESIGN.md`.
For personal facts and project claims, consult `docs/content-sources.md`.
